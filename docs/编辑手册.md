# 编辑手册

给全球退党服务中心的编辑。遇到「我改了，网站上怎么没变」「这个视频为什么放不出来」这类问题，先翻这里。

最后更新：2026-10-20

---

## 一、保存之后到底发生了什么

这一节解释一件最容易让人困惑的事：**你保存了，网站什么时候变？**

答案是：**立刻**。但中间有几步，知道了就不会疑神疑鬼。

### 网站为什么不是「现查现做」

网站上的页面是**事先做好的 HTML**，访客来了直接发给他，不去查数据库。这样做有两个原因：快，以及**扛得住攻击**——2026 年 10 月 13 日本站遭到每秒三万五千次请求的攻击，数据库被打垮、网站瘫痪了几个小时。改成事先做好之后，同样的攻击打在缓存上，碰不到数据库。

代价是：数据库里的内容变了，事先做好的那份 HTML 就过时了。所以需要下面这套流程。

### 四步

```
① 你点「保存」
   内容写进数据库，系统同时把受影响的页面标记为「过时」
   ⚠️ 这一步不重新生成页面，只是打个标记，所以保存很快

② 系统立刻在后台把最重要的几页重新做一遍
   文章：首页、新闻页、这篇文章自己
   视频：首页、视频页、这个视频自己
   资料：它所在的分类页、这份资料自己
   你看不见这个过程，它在你的浏览器后台悄悄进行

③ 你点过去看
   因为第②步已经做好了，你看到的就是新内容，而且很快

④ 其它受影响的页面（分类页、归档页）
   等第一个访客来看的时候才重新做，那个人会慢一两秒，之后所有人都快
```

**所以：保存完直接点「在站点查看」，看到的就是新的。** 不需要等，不需要刷新很多次，更不需要去点那个「强制刷新全站缓存」。

### 一篇文章改动会影响多少页面

一篇文章不只出现在它自己的页面上——标题在首页、在新闻页、在它的分类列表、在归档里。所以保存一次，系统会把 **15 个地址**标记为过时：

| | 个数 |
| --- | --- |
| 文章自己 | 1（改了网址的话是 2，新旧都清） |
| 首页 | 1 |
| 新闻首页 | 1 |
| 四个特殊栏目（最新、归档、重要、精彩保留） | 4 |
| 全部八个分类 | 8 |

为什么连不相干的分类也清？因为「最新发布」和「全部文章」对任何一篇文章都会变，而把文章从一个分类挪到另一个会同时改变两个列表。全部标记一遍比算来算去更可靠，而且**打标记几乎不花时间**。

### 哪些改动会立刻生效

**全部都会。** 下面这些保存后公开页面立刻更新，你不需要做任何额外的事：

- 文章：新建、修改、删除、批量操作、审核
- 视频：全部六种操作
- 页面内容（关于我们、参与支持、资源馆、服务页等）
- 资料、资料分类
- 常见问答、问答分类
- 文章分类
- 主题与排版
- 版本回滚

### 草稿和发布的区别

- **保存草稿**：只存进数据库，公开网站上**没有**这个页面，访问它的网址会显示「页面不存在」。
- **发布**：公开网站上立刻能看到。

想在发布前看看效果，用文章列表里的 **「预览」** 链接（`/admin/preview/...`），那是专门给编辑看草稿的地址，不需要发布。

### 「强制刷新全站缓存」按钮：几乎永远不要用

这个按钮在概览页，只有管理员能看到。它会把**全站一万五千多篇文章的缓存全部丢掉**，之后每一个被访问的页面都要重新查一次数据库——在网站正被攻击的时候，这正是当初把数据库打垮的那件事。

**你不需要它。** 你保存的任何东西都会自己更新。只有在「某个页面明显卡住了旧内容、而且找不出原因」时，才请管理员点它。

## 二、怎么放视频

本站有两个地方会用到视频：**视频库**（左边菜单「视频管理」，每个视频是一条独立内容），以及**文章正文里插入的视频**（编辑器工具条上的「▶ 视频」按钮）。两处支持的地址是一样的。

### 支持四种来源

| 来源 | 粘贴什么地址 | 说明 |
| --- | --- | --- |
| **干净世界** | 浏览器地址栏里的地址即可 | 系统会自动转成可播放的形式 |
| **YouTube** | 观看页、分享短链、嵌入链接都行 | 三种都认 |
| **Vimeo** | 浏览器地址栏里的地址即可 | 系统会自动转换 |
| **自有文件** | 以 `.mp4` / `.webm` 结尾的直链 | 见下面「上传文件」 |

### 重要：直接粘浏览器地址栏就行

干净世界和 Vimeo 有一个共同的坑：**它们的观看页面不允许被嵌入**。

- 干净世界的 `/video/...` 地址：浏览器会拒绝显示，而且**什么错都不报**，页面上就是一片空白。
- Vimeo 的 `vimeo.com/...` 地址：会显示一个破碎的图标。

**本站已经替你处理了，而且是两层：**

1. **后台会提醒你。** 粘进去之后它会说「这是干净世界的 `/video/` 地址，播放器嵌不进去」，把你填的地址和改好的地址并排列出来，给一个**「改成 /embed/」按钮**。点一下就好。它**不会偷偷替你改**——你填的是什么，保存的就是什么。
2. **就算你没点那个按钮，公开页面也会自动修正。** 实测确认过：故意不点按钮直接发布，读者看到的播放器用的仍然是能播的那种地址。

所以：**看到什么地址就粘什么地址，不用自己去找「嵌入代码」。** 看到那个提示，顺手点一下按钮最省事；忘了点也不会出事。

### Vimeo 的未公开影片

如果是未公开（unlisted）的 Vimeo 影片，地址会长这样：

```
vimeo.com/338376050/a1b2c3d4e5
          ↑影片编号  ↑这串是钥匙，必须一起粘进来
```

**后面那串不能漏**，漏了就放不出来。整条地址一起复制即可。

### 封面图：点一下「自动获取封面」就行

封面图那一栏标了 **\***，是必填的。但多数情况下你不用自己找图：

**填好视频地址之后，点「自动获取封面」。** 系统会去 YouTube／干净世界／Vimeo
取这支片子自己的封面图，存到本站，几秒钟就好。

| 来源 | 取的是什么 |
| --- | --- |
| YouTube | 平台的最高清封面（取不到就自动退到次一级） |
| 干净世界 | 影片页上的封面图 |
| Vimeo | 平台公开接口给出的封面图 |

取回来的图**存在本站**，不是直接用平台的地址。这样平台那边改了或挂了，我们的
页面照样有图。它也会进「图片视频库」，以后可以重复使用。

**如果取不到**（比如地址是一个 .mp4 文件），它会告诉你，这时手动「选择或上传」
一张。

### ⚠️ 为什么封面是必填的

首页的「影音节目」区**只收有封面图的视频**。没有封面的视频：

- 正常发布，在 `/videos` 和分类页里都有
- **唯独首页没有**——而且后台不会说一句话

这是编辑最容易踩、又最难自己发现的坑，所以现在直接在发布时拦下来。

**文章没有这个限制**：一篇没有封面图的文章照样会上首页。两者不一样，实测确认过。

**一个例外**：旧站搬过来的那些只有文字稿、没有播放器的集数，没有视频地址也就
没有封面可取。这种情况不拦——没填视频地址时，封面不是必填的。存草稿也从不拦。

### 系统不会自己「生成」封面

说明一下区别：系统是去平台**取现成的**封面，不是从影片里截一帧。影片在别人的
服务器上，我们截不了。

另外，视频**详情页**其实不受影响——那里嵌的是平台自己的播放器，它会显示自己的
封面。出问题的只有列表卡片和首页：没有封面的地方就是一块纯色方块，没有默认图。

### 视频库里的两个地址栏

新建视频时有两个地址栏：

- **视频地址**：主要播放地址
- **干净世界备用地址**：备用

建议两个都填——两个平台的可达性不一样，填两个更稳。

### 文章正文里插视频

正文编辑器工具条 → **「▶ 视频」** → 粘贴地址 → 可以再写一行说明文字（显示在播放器下面）。

## 三、用本站系统做视频（影片拼接台）

左边菜单 **「影片拼接台」**。它用来把若干段素材剪成一条片子。

工作顺序就是实际做片子的顺序：

1. **放入素材** —— 指定源文件
2. **找片段** —— 在素材里挑出要用的那几秒
3. **排顺序** —— 把挑出的片段排成一条
4. **配乐** —— 铺底乐（可设循环、节拍、音量）
5. **看粗剪** —— 先看一遍
6. **渲染** —— 生成成片
7. **发布** —— 成片可以作为视频内容发布

它不是那种拖拽色块的时间线。每一刀都是「某部片子的第几秒到第几秒」，用写明数字的列表记录——比拖拽更精确，而且**半年后再打开还看得懂自己当时在干什么**。

做好的片子和用命令行做出来的是同一个东西，项目文件存成 `projects/*.json`，两边通用。

## 四、上传文件

### 怎么上传

文件**不经过本站服务器**，由你的浏览器直接传到存储服务。所以大文件也传得动。

但上传前系统会先检查：登录状态、你的角色权限、文件类型、文件大小——都通过了才给你一张上传凭证。

### 限制

- **单个文件最大 200MB**
- **允许的类型**：
  - 图片：jpg、png、webp、gif、avif
  - 文档：pdf、zip、rar、doc、docx
  - 音频：mp3、m4a、wav、ogg
  - 视频：**只有 mp4 和 webm**
  - 设计稿：ai、psd

### 视频只能传 mp4 和 webm

`.mov` 和 `.avi` **传得上去，但在网页里放不出来**——浏览器不认，页面上一片空白，而且不报错。这是最容易踩的坑之一。

从手机或相机拿到 `.mov` 文件，先转成 mp4 再传。

### 图片说明（Alt）请一定填

读屏软件会把这句话念给视障读者听。**没有它，这张图对他们等于不存在。**

## 五、资料（Materials）

### 资料的网址比想像的深一层

一份资料的公开网址是：

```
/resources/downloads/<分类>/<资料代号>
```

比如「展板与横幅」里的一份资料，地址里会带 `downloads/boards/`。它出现在**它所在
的分类页**上（例如「展板与横幅」那一页），**不在**资源馆首页、也不在下载总览页上
——那两页列的是分类，不是单份资料。

所以保存后要检查效果，点进它的分类页看，不要在资源馆首页找。

### 资料只能归档，不能删除

资料的按钮是「发表／存草稿／归档」，没有「删除」。**归档**之后它从公开网站上消
失，但记录还在后台。这是有意的——资料常常是过一段时间又要用的。

（文章和视频有「删除」按钮，删了就真没了，后台也撤不回来。）

## 六、几件值得知道的事

### 文章和影片末尾的分享块（2026-10 新增）

每篇文章、每支影片读完之后，底部有一块分享区。**不需要你做任何事，自动就有。**

里面两样东西值得专门说：

**短地址。** 每条内容在入库那一刻就发一个短码，形如 `tuidang.org/a/SRUTnr5`（影片是 `/v/`）。
分享块左边显示的就是它，点一下即复制。它短、全是英文字母数字，微信、短信、口头念都不会断。

**二维码。** 短地址的二维码，点「二维码」放大，可以下载成图片。微信没有网页分享接口，
扫码是唯一的路 —— 做展板、传单、易拉宝需要二维码时，从这里取，不用另外生成。

短码**绑在这条内容上，不绑地址**。以后改网址、改标题，短地址和二维码都不会失效，
印出去的东西不会变成废纸。

### 图片和视频文件，和页面是两回事

上面讲的「保存→更新」管的是**页面文字**。图片、音频、视频**文件本身**存在另一个地方（Supabase Storage），是读者的浏览器拿到页面之后，再单独去取的。

所以可能出现：页面文字是新的，图片却显示不出来。那是存储服务的问题，不是你保存得不对。遇到这种情况告诉技术人员，不要反复重存。

### 网址现在是拼音（2026-10 改的）

2026-10-19 起，全站文章和影片的网址一律是 **日期 + 拼音**，例如：

    /news/2026-10-19-jin-nian-qian-san-ji-yu-qian-wan-ren-san-tui

以前是中文，像 `/news/今年前三季逾千万人三退`。中文地址粘到别处会变成
`%E4%BB%8A%E5%B9%B4%...` 一长串乱码，很难看，也容易被截断 —— 换拼音就是为了这个。

**新建内容不用管。** 填完标题，网址会自动按拼音生成，日期取的是**这一篇的发布时间**
（不是今天），所以回填旧日期也对。不满意可以自己改，或点「由标题重新生成」。

**旧的中文地址全部继续有效**，会自动跳到新地址。已经发出去的链接、搜索引擎收录的，
都不会断。

### 改网址（slug）：旧链接不会断，但别反复改

文章发布之后再改网址，**旧地址会自动跳到新地址**，不再像以前那样变成 404
（2026-10-12 改的，手册这一段原先写的是旧情况）。

不过还是别当成没代价：每改一次就多留一条跳转记录，而跳转比直达慢一点。
确实需要改就改，不要为了措辞反复调。

想分享又怕地址变，用分享块里的**短地址**——它绑在内容上，改网址也不会失效。

### 搜索是实时的

站内搜索直接查数据库，**内容一发布就能搜到**，不需要等同步。

三退声明和退党证明不在本站搜索范围内——那两项由 `santui.tuidang.org` 和 `service.tuidang.org` 提供查询。

### 找不到自己改的东西？按这个顺序查

1. **是不是存成草稿了？** 草稿在公开网站上不存在。看状态栏写的是「草稿」还是「已发布」。
2. **是不是看错页面了？** 用列表里的「预览」链接，它一定指向正确的地址。
3. **换个浏览器或无痕窗口看看。** 有时是你自己浏览器的缓存，不是网站的。
4. 以上都不是 → 找技术人员。**不要去点「强制刷新全站缓存」。**

## 附：这套机制为什么是这样

2026 年 10 月 13 日，本站遭到持续的大规模攻击，峰值每秒三万五千次请求，25 小时累计十六亿次。数据库被打到拒绝连接，网站瘫痪数小时。

根本原因是：文章页面当时是「每次有人看就现查一次数据库」。攻击者反复请求同一篇 2013 年的旧文，每一次都变成一次数据库查询，连接池很快被占满。

改成「事先做好 HTML」之后，同样的攻击打在缓存上，碰不到数据库。代价就是本手册第一节讲的那套流程——保存之后需要让系统知道哪些页面过时了。

技术细节见 `docs/implementation/attack-solution/tuidang.org DDoS 事件与防御.md`。
