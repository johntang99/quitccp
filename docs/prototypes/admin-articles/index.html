设计说明与待决问题

四个页面：A 新建 · B 查找与修改 · C 最新 100 篇 · D 文章统计，以及 B/C 点进去的 编辑页。

现状：目前的「文章管理」只能看，不能写

现有 /admin/articles 只有列表、审校下拉与删除——没有任何新建或编辑文章的界面。 写入接口 POST /api/admin/content/articles 是有的，但没有页面用它。所以这不是改版，是补上缺的一半。

现有接口已支持：slug、标题、栏目、语言、状态、单个分类、标签、正文 Markdown、旧站 ID。

需要新增的数据字段

设计稿里有几个字段数据库还没有。它们需要一次迁移 （010_article_editorial_fields.sql），和之前的分类排序一样要手工执行。

字段用途现状
subtitle副标题无，需新增
hero_image / hero_image_alt / hero_credit封面图与说明无，需新增
author / translator署名无，需新增
source_title / source_url转载来源与 canonical无，需新增
published_at发布时间表里已有，但写入时没填——需要改代码，不需要迁移
summary摘要已有，但目前是正文前 240 字自动截断，需改成可人工编辑
副分类一篇文章归多个栏目表结构已支持（cms_article_category_map 是多对多），只是代码里写死了一个分类

几个我替你做了主的决定，如果不同意请说

  1. 摘要与副标题分开。副标题给读者看（显示在标题下），摘要给列表卡片和搜索引擎用。合成一个会让两边都别扭。
  2. slug 只在标题第一次填完时生成，之后不再自动跟着标题变。否则改一个错字就会换掉已发布文章的网址。
  3. 删除默认劝人改用「归档」，并告诉你有多少站内链接会因此断掉。一千多篇迁移文章彼此有互链，误删的代价不小。
  4. 发布时间可回填也可填未来。回填是迁移旧文必需；未来时间即定时发布。
  5. 转载来源会写进 rel=canonical，避免转载稿被搜索引擎判成抄袭。
  6. 封面图说明（alt）列为必填。缺了它图片对视障读者等于不存在，而这是一个以「可检验、可公开」为立场的站点。
  7. 正文用 Markdown，不做所见即所得。现有一千多篇迁移内容已经是 Markdown，换富文本会引入一次有损转换。

请你拍板的问题

  1. 审校流程要不要真的用？现在有 draft／review／published／archived 四态和一个审校接口。 如果实际上只有你一个人发稿，建议简化成「草稿／已发布」，少两次点击。
  2. 作者是自由文本还是一份名单？自由文本上手快但会出现「编辑部」「編輯部」「编辑室」三种写法； 名单干净但要先维护一份人员表。设计稿用的是「自由文本 + 历史值提示」的折中。
  3. 要不要定时发布？需要一个定时任务去把到点的文章翻成已发布，Vercel 上用 Cron 即可，但要额外搭。
  4. 英文版怎么处理？现在 locale 字段有 zh/en，但没有「这两篇是同一篇的中英文」的关联。 如果计划做多语言，这个关联要现在就设计进去，后补很痛。
  5. C 页的「最新 100 篇」按发布时间还是更新时间排？设计稿按发布时间，未发布的按更新时间插进来。
  6. 图片上传走哪里？沿用首页那套媒体库（Supabase Storage + cms_media_assets）， 还是给文章单独开一个空间？建议沿用，图片可跨文章复用。

实现顺序（确认设计后）

  1. 迁移 010_article_editorial_fields.sql（需要你手工执行一次）
  2. 仓储层：新字段读写、副分类多对多、published_at、人工摘要
  3. 编辑页与新建页（共用一个表单组件）+ Markdown 编辑器
  4. B 查找与修改：筛选、分页、批量操作、删除确认
  5. C 最新 100 篇（B 的简化视图，复用同一张表格）
  6. D 统计（若干 count 查询 + 数据质量筛选链接）

前四步做完就已经可以正常发稿；C 和 D 是锦上添花。
