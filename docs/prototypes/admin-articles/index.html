四个页面：A 新建 · B 查找与修改 · C 最新 100 篇 · D 文章统计，以及 B/C 点进去的 编辑页。

你的七个答复，已落到设计里

1 审校流程取消。状态只剩 草稿 / 已发布。
「已归档」保留，但不出现在状态下拉里——它是删除的替代品，只在删除确认里出现，日常发稿仍是两态两次点击。
2 作者自由文本。默认填入当前登录者的名字；下拉列出站内用过的署名，点一下复用。不做人员表。
3 定时发布不做。发布时间默认此刻、可回填旧日期；填未来时间会提示。
4 英文版只做中文。语言选择已从表单与筛选中移除，数据库的 locale 字段保留不动。
5 最新 100 篇排序按 更新时间 倒序。
6 图片上传沿用首页那套媒体库（Supabase Storage + cms_media_assets），图片可跨文章复用。
7 Slug见下一节——查过数据之后，我的建议和设计稿原本的写法不一样。

关于第 7 题：查过数据库之后

站内现有 10,000 篇文章的网址全部是中文。随手抽几条：

/news/《九评共产党》之九：评中国共产党的流氓本性
/news/任世豪：孔子学院改名易帜-慎防中共大外宣（图文
/news/范仲淹：先天下之忧而忧

所以「编辑英文不好」这件事，其实早就不是问题——这个站一直在用中文网址。 我原来的设计稿写成英文 slug 是错的：新文章若用英文，站里就会有两套互不相干的网址风格。

三种做法

做法样子代价
① 中文，由标题自动填
建议		 全球退党中心：三退大潮宣告镇压破产 编辑一个字都不用改，和现有一万篇一致。复制到纯文本时会变成 %E5%85%A8%E7%90%83…，看着长。
② 拼音＋日期 2026-09-27-quan-qiu-tui-dang-zhong-xin 纯拉丁、也不需要英文，但和现有一万篇不一致，站里会有两套风格。
③ 机器翻译成英文 2026-09-27-quit-ccp-rally-washington 最好看，但要调翻译接口；译错了会永久留在网址里，改网址就断链接。

我的建议是 ①，并且把 ② 做成一个按钮：默认中文自动填好， 谁想要拉丁网址点一下就变成拼音。设计稿现在就是这样。

顺带一提：现有中文 slug 里混着 《》：（ 这些标点，其中有的还被截断了（「…（图文」）。这是迁移脚本留下的， 可以单独做一次清洗，不影响这次的功能。

另外两件查出来的事

  1. 分类页的文章数是错的，已修好。原本一次把整张关联表取回来再统计，而 PostgREST 单次最多返回 1000 行——所以「新闻」显示 0，真实是 7,785。现在改成每个分类各查一次 count。 这是线上的真实数字错误，不是设计稿的事，已经改了。
  2. 文章其实有 10,001 篇，不是一千篇，而且 7,785 篇（78%）都堆在兜底分类「新闻」下， 新建的五个分类全是 0 篇。这会让 B 页的批量改分类从「锦上添花」变成主力工具—— 把这近八千篇归位，是这套后台上线后的第一件正事。

实现顺序

  1. 迁移 010_article_editorial_fields.sql（你手工执行一次）
  2. 仓储层：新字段读写、副分类多对多、published_at、人工摘要、两态状态机
  3. A 新建 / 编辑页（共用一个表单组件）+ Markdown 编辑器 + 媒体库接图
  4. B 查找与修改：筛选、分页、批量改分类、删除确认
  5. C 最新 100 篇（B 的简化视图，复用同一张表格）
  6. D 统计

做完前四步就能正常发稿，并且可以开始给那 7,785 篇归类。
