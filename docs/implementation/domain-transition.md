# 新旧网站切换方案（tuidang.org）

> **切换日：2026-10-09（周五）** —— 当天起编辑只用新后台，不再使用 WordPress
> 最后更新：2026-10-06

把主域名 `tuidang.org` 从现有 WordPress 站切换到新站（目前在 `quitccp.vercel.app`），
同时把继续由老站提供的功能拆到各自的子域名。

本文只写**技术约束与执行步骤**，便于技术组对齐。文中数字均为生产数据库实测，不是估计。

## 3. 切换前的增量同步

老站在切换前仍在发文。切换当天新站必须已经有这些内容，否则读者会发现主域名上少了最近
几周的文章。

**2026-10-06 已跑通，并补上了当时缺的 8 篇。**

### 3.1 怎么跑

```bash
node --env-file=.env.local scripts/sync-from-old-site.mjs            # 空跑，只看会导入什么
node --env-file=.env.local scripts/sync-from-old-site.mjs --apply    # 真正执行
```

起点不用自己填：脚本取「带 `legacy_id` 的最新一篇文章」的发布日期往回退一天作为
`--after`（我们自己在 CMS 里写的文章没有 `legacy_id`，所以不会把起点顶到未来、导致漏拉）。
导入按 `slug + locale` 去重，重复跑不会产生重复文章。

一次运行依次做四件事：**拉取 → 导入文章 → 导入影片 → 把新文章带来的图片转存到我们自己
的存储**。最后一步很重要：不做的话，每同步一次就新增一批对老站的依赖，第 2 节刚清掉的
问题又会长回来。

**建议切换前每周跑一次，切换当天再跑最后一次。**

### 3.2 一个需要知道的前提：直连被 Cloudflare 挡着

实测（2026-10-06）老站的机器可读接口全部返回 403 —— 用真实 Chrome、带完整挑战 cookie、
同源请求也一样：

| 入口 | 直连结果 |
|---|---|
| `/wp-json/wp/v2/posts`（REST API） | **403** |
| `/feed/`（RSS）、`/sitemap.xml` | **403** |
| `/category/…`、`/page/2/`、单篇文章页 | **403** |
| 首页 `/` | 200（真实浏览器；curl 仍是 403） |

**但同步仍然能跑**：`scripts/migrate-wp-posts.ts` 内置了读透代理兜底
（`r.jina.ai`），当直连被挑战时自动改走代理 —— 当初那 15,514 篇也是这么拉下来的。

**这是个脆弱的依赖**：第三方代理，我们不控制，哪天失效同步就断。

> **建议向老网站管理员提的请求**：在 Cloudflare 加一条 WAF skip 规则，对
> `/wp-json/wp/v2/` 放行（可限定我们的来源 IP）。管线其余部分一行都不用改，只是不再
> 依赖代理。

### 3.3 影片：优先用 YouTube 与干净世界

影片不是单独的内容源，而是从同一批文章里挑出来的（`scripts/allocate-videos.ts` 按
「是否有播放器 / 是否属于影片系列」分组）。

**原则：影片一律引用平台地址，不放进我们自己的存储。** 文件留在 YouTube／干净世界，
我们只存地址 —— 不占空间、不占流量、不需要我们维护播放。

2026-10-06 据此把 orphan 里带平台播放器的那批收进了影片库：

| 分组 | 数量 | 处理 |
|---|---|---|
| series / tagged / rescue | 745 | 一直在影片库 |
| orphan，带 YouTube／干净世界 且**实测可播** | **160** | **已收入**（10-06） |
| orphan，带平台地址但**已失效** | 31 | 不收 —— 收进来就是 160 个打不开的播放器 |
| orphan，播放器是别人服务器上的裸 .mp4 | 259 | 暂不收（ntdtv 232、inews3 26、minghui 1），这类链接容易烂 |
| orphan，没有播放地址 | 272 | 不是影片，作为文章照常可读 |

影片总数 745 → **905**。

失效判定不是看扩展名，是**逐条问过**：`scripts/verify-platform-videos.mjs` 用 YouTube
oEmbed 核对每个地址（注意正文里是 `/embed/<id>` 形式，oEmbed 只认 watch 地址，直接拿
embed 地址去问会 191 条全报 404）。核对结果写进
`artifacts/phase5/platform-orphans-live.json`，导入时只认这份名单：

```bash
node --env-file=.env.local scripts/verify-platform-videos.mjs
npx tsx scripts/import-videos.ts --include-platform --apply
```

### 3.4 ⚠️ 重跑影片导入后必须做的两件事

影片导入会**重算**每行的字段，两次踩过坑，现已加保护，但仍建议每次核对：

1. **播放地址**：它会用老文章正文里的地址覆盖 `source_url`，把我们辛苦改好的
   185 条干净世界、18 条 YouTube、19 条待上传**全部清空**。现在的规则是「已有地址的行
   不动，只填空的」，运行时会打印 `保留了 N 条已存在的播放地址`。**没看到这行就要查。**
2. **分类**：它会重写 `cms_video_category_map`，把
   `scripts/fix-video-categories.mjs` 的修正冲掉（九评系列会从 9 条涨回 46 条）。
   **每次影片导入后重跑一次那个脚本。**

### 3.5 后台：编辑能改的，和不能改的

**新闻与影片的列表来自数据库，后台不管这部分。** `/news` 由 `getNewsHome()` 生成，
`/videos` 与各影片分类由 `getVideoHome()` / `getVideoCategory()` 生成 —— 文章和影片
自动上架，不需要也不应该在页面内容里手工维护。

据此在 2026-10-07 把 **27 个条目**从「页面内容」列表里隐藏了，它们编辑后都不会有任何
效果：

| 原因 | 数量 | 条目 |
|---|---|---|
| 页面 404（路由已不存在） | 18 | news 的 7 个旧菜单地址、resources 的 11 个书籍／杂志详情页 |
| 页面正常，但由数据库驱动、不读这个条目 | 9 | `news/index`、`videos/index` 及 7 个影片分类 |

隐藏后「页面内容」从 60 条减到 **33 条，全部是表单，没有一个 JSON 框**。

**数据没有删除**，只是不显示；把路径从 `UNEDITABLE_PATHS` 里拿掉就会重新出现。

> 代价要说清楚：`/news` 和 `/videos` 页面上的文案（「按栏目浏览」这类）目前写在组件里，
> 编辑改不了。**这不是隐藏造成的** —— 那些条目本来就不生效。若要让编辑能改这部分文案，
> 需要把这些字串接到 CMS，是一件独立的小工程。

## 4. 主域名接入 Vercel

Vercel 按 HTTP `Host` 头路由请求，域名必须**先在 Vercel 项目中登记**，平台才知道把
`tuidang.org` 交给哪个项目；HTTPS 证书也是在域名登记且 DNS 指向正确之后自动签发。
所以顺序不能颠倒。

### 顺序

1. **（我）** 在 Vercel 项目中添加 `tuidang.org` 与 `www.tuidang.org`
2. **Vercel 给出具体 DNS 记录**，通常是：
   - apex（`tuidang.org`）→ A 记录 `76.76.21.21`
   - `www` → CNAME 指向 `cname.vercel-dns.com`
   - 服务商若支持 ALIAS/ANAME，apex 用它比 A 记录更稳
3. **（老）** 按给出的记录修改 DNS
4. 等证书自动签发完成后再对外公布

> DNS 目前托管在 **Cloudflare**（`laura.ns.cloudflare.com` / `major.ns.cloudflare.com`），
> 主域名与子域名都开着橙云代理。若主域名继续保持橙云，Cloudflare 的 SSL 模式必须是
> **Full (strict)**，且 Vercel 首次签发证书时需要把该记录临时切成灰云，签完切回。
> 最省事的做法是**主域名改走灰云（DNS only）**，让 Vercel 自己处理 CDN 与证书。

### 两个容易出事的点

- **不要动 MX 与 TXT（SPF／DKIM）记录。** 改 A 记录本身不影响邮件，但如果顺手整理
  DNS 时清掉了 MX/SPF，机构邮箱会立刻收不到信。这是域名迁移最常见的事故。
- **提前 24–48 小时把相关记录 TTL 降到 300 秒。** 否则一旦需要回滚，要等旧 TTL 自然
  过期（可能几小时到一天），期间毫无办法。切换稳定后再调回去。

### 老站侧

把 `/donation/` 和退党证明服务迁到子域名时，WordPress 数据库里存的是**绝对地址**，
需要做一次 search-replace，否则页面仍会输出旧的 `www.tuidang.org/...` 链接。

### `NEXT_PUBLIC_SITE_URL` —— 切换当天必须改

新站用这个环境变量生成 `canonical`、`robots.txt` 的 Host／Sitemap 行，以及
`sitemap.xml` 里的全部地址。

| 时间 | 值 |
|---|---|
| 现在（测试期） | `https://quitccp.vercel.app` ✅ 已设置 |
| **切换当天** | **改成 `https://www.tuidang.org`**，然后**重新部署** |

环境变量在构建时写入，不重新部署不生效。代码里的兜底值就是
`https://www.tuidang.org`，所以当天**直接删掉这个变量**效果相同，且不会再忘。

目标是让 `services.tuidang.org` 的页头、菜单与新站看起来是同一个网站。

做法：**把新站页头的 HTML + CSS 整理成独立片段，贴进 WordPress 主题的 header 模板。**

- 一次性工作，之后两站完全独立
- 地址栏、收藏、分享、后退键、SEO 全部正常，不涉及跨域
- 日后新站页头改版时需要重新导出一次片段

片段已经做好，在 `docs/handoff/` 目录，可直接交付：

| 文件 | 内容 |
|---|---|
| `header-snippet.html` | 页头 HTML，3.3KB，链接与图片已全部绝对化 |

## 6. 老链接的重定向

**已经做好**：新站内置 `cms_redirects` 共 **15,513 条**老 URL → 新 URL 映射，由
`apps/web/src/middleware.ts` 在请求时查表并发 301。历年文章的老链接（`/2024/...`、
`/2023/...` 这类）不会断。这部分老网站管理员不需要操心。

**还需要补**：子域名路径结构确定后，补两类 301 ——

- `tuidang.org/donation/` → `donation.tuidang.org`
- 退党证明服务的各路径 → `services.tuidang.org/...`

这些地址印在传单、海报、名片上，也被大量外部网站引用。301 能让旧地址继续可用，而不是
让拿着传单的人看到 404。

## 7. 安全

- **Cookie 作用域**：子域名拆分后，Cookie 应限定在各自主机名上，不要设成
  `.tuidang.org`（父域通配）。否则新站与老站共享会话状态，一边的问题会波及另一边。
- **声明数据**：声明与证明数据仍在老站，新站不接触。查询入口继续指向
  `service.tuidang.org` 与 `santui.tuidang.org`，新站站内搜索**不包含**任何声明数据。
