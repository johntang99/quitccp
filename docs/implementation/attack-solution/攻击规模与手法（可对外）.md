## 一句话

2026 年 10 月 12 日至 15 日，全球退党服务中心网站遭到持续数日的应用层
DDoS 攻击。峰值时每小时 3.482 亿次请求，约合每秒 9.67 万次；25 小时内
累计约 40.6 亿次。网站数据库被打到拒绝连接，站点一度全线不可用数小时。

## 规模

| | |
| --- | --- |
| 峰值速率 | **每秒约 96,700 次请求**（10 月 14 日 12:00 UTC） |
| 单小时峰值 | **3.482 亿次** |
| 25 小时累计 | **约 40.6 亿次** |
| 本站正常流量 | 每小时约 1,500–2,000 次 |

换成能感受的说法：

- 攻击峰值是本站正常流量的 **约二十万倍**。
- 那 25 小时里打进来的请求量，相当于本站 **265 年**的正常访问量。
- 单篇文章承受了 **20.7 亿次**请求 —— 而全站一共才 15,374 篇文章。

## 手法

这不是靠灌带宽把网线堵死的那种攻击，而是冲着后端算力去的**七层 HTTP
Flood**。特征很清楚：

**缓存绕过。** 每一个请求都挂上一个随机参数。内容分发网络看到的是「一个
从没见过的新地址」，只能回源重新生成 —— 攻击者用极低成本强迫我们这边做
极高成本的计算。这是这场攻击最核心的一招。

**高度集中的来源。** 28.7 亿次请求来自单一自治域（3xK Tech GmbH，
AS200373，德国）；绝大多数请求共享同一个 TLS 指纹。真实读者群不可能这样
聚集 —— 这是同一套程序在同一批机器上跑出来的。

**伪装成浏览器。** User-Agent 在 Chrome 121/133/134/135/136、Android 14
之间轮换；请求方法 GET、HEAD、POST 混用。

**中途换过地址。** 攻击进行到一半，对方改用那篇文章的**旧版 WordPress
地址**继续打 —— 说明对面在观察效果并调整打法，不是一套脚本从头跑到尾。

**单点定向。** 靶心是 2013 年的一篇旧文，关于一位中共政治人物。这不是
随机扫到的目标，是挑好的。

## 为什么确定不是真实读者

最硬的一条证据来自一个简单的比例：**真实浏览器打开网页，必然会去加载页面
的样式表。**

那篇被攻击的文章，HTML 请求数是 CSS 请求数的 **十万倍量级**。

没有任何人类读者群会呈现这个比例。这些请求甚至不打算假装自己是浏览器。

## 在业内算什么级别

把它放进公开数据里看，结论是两面的。

### 按峰值速率：高于大多数，但远非纪录

Cloudflare 的季度 DDoS 报告显示，**63%–81%** 的 HTTP DDoS 攻击峰值不超过
每秒 5 万次请求（2024 Q2 为 81%，2024 Q4 为 63%，2025 Q2 为 65%）。我们
这次约 9.67 万次/秒，落在高于这条线的那一档里。

但有公开记录的最大单次 HTTP Flood 是**每秒 7,100 万次**（Cloudflare，
2023 年 2 月），后续报告中还有超过 2 亿次/秒的说法。按这个标尺，我们挨的
这一下是它的约千分之一。

### 但速率不是唯一的刻度，甚至不是最重要的那把

**持续时间。** 那些创纪录的攻击往往只持续几十秒 —— Cloudflare 2025 年挡下
的 31.4 Tbps 那次只有 35 秒。我们这次是以极高强度**连续打了好几天**，而且
分波次、反复加码。

**目标体量的错配。** 每秒 9.67 万次对一家大型商业平台可能只是一次告警；
对一个由志愿者维持、正常流量每小时一千多次的非营利网站，这是两万倍于
日常的压力，性质完全不同。

**意图不是让你宕机一下，是让你付不起。** 随机参数绕过缓存、专挑一篇文章
反复打 —— 这套打法的收益不在于那几个小时的中断，而在于把网站的运行成本
推到难以承受。事实上，整个月的基础设施账单几乎全部产生在 10 月 12、13、
14 这三天：28 天的用量图上只有三根柱子，**账单的形状就是攻击的形状**。

### 准确的定位

这不是一次创纪录的超大规模攻击，而是一次**规模可观、技术成熟、针对性极强
且持续数日的定向攻击** —— 目标明确是一家非营利机构的一篇特定文章，打法
针对的是运营成本而非一时的可用性。

## 造成了什么

- 数据库连接被耗尽，站点全线不可用数小时（10 月 13 日）。
- 基础设施开支在三天内集中产生，远超日常。
- 攻击流量的地理来源以德国（1.872 亿）、美国（1.639 亿）、加拿大
  （9,100 万）为主 —— 也就是我们真实读者所在的地方，这使得「按国家封锁」
  不是一个可用的选项。

## 时间线（美东时间）

| 时间 | 事件 |
| --- | --- |
| 10-11 ～ 10-12 | 数据库 CPU 从 20% 阶跃到 70%，事后判断为小规模试探 |
| 10-13 02:00 | 攻击规模化 |
| 10-13 05:16 | 数据库不可达，站点全线不可用 |
| 10-13 全天 | 攻击持续加码 |
| 10-13 深夜 | 攻击者换用旧版 WordPress 地址继续打 |
| 10-14 08:00（12:00 UTC） | **峰值**：该小时 3.482 亿次请求 |
| 10-15 ～ 10-16 | 强度逐步回落 |
