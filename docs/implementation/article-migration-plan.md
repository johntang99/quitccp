## 已经做好的工具

`scripts/check-wp-taxonomy.ts` —— **只读**，不写库、不写盘。拿到导出文件后先跑它：

```bash
npx tsx scripts/check-wp-taxonomy.ts --wxr path/to/export.xml
```

它会列出旧站每个分类的名称、slug、已发布文章数，并分成「已覆盖」与「未覆盖」两栏，
最后给一个覆盖率。**覆盖率不到 100% 就不要导入**——上次正是因为对照表只猜中 3 个分类，
7,785 篇（78%）落进了兜底分类「新闻」。

对照表本身在 `scripts/migrate-wp-posts.ts` 的 `taxonomyMap`，现在同时按
**中文名称**和 slug 两种键匹配（上次只按 slug 猜，四个猜错的一篇都没匹配上）。

## 建议的步骤

1. 你从 WordPress 导出 WXR 文件。
2. 跑 `check-wp-taxonomy.ts`，把未覆盖的分类补进对照表，直到覆盖率 100%。
3. **先导 1,000 篇以内做试验**（`import-normalized-posts.ts` 支持 `--dry-run`），
   检查分类分布、资料区是否分出来了、跳转是否正确。
4. 试验没问题，再清空 `cms_articles` 与 `cms_article_category_map` 重导全量。
   清空前先导一份现有数据备份——现有一万篇的正文是干净的，只有分类是错的。
5. 重导后核对：各分类篇数、`section = resources` 的篇数、301 跳转数量。

> 第 4 步的清空是不可逆的。等第 3 步确认无误、并且备份存在，再执行。
