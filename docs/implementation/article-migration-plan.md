## 「新闻」分类

新站不该有「新闻」。它现在存在、且挂着 7,785 篇，所以**不能直接删**——
要等重新导入把这些文章归到正确分类之后，它变成 0 篇才能删掉。
新的对照表里没有任何一条指向它，重导之后它自然清空。

## 步骤

**第 0 步 · 代码准备（已完成）**
- 对照表按 51 个真实分类重写，覆盖率 100%
- **取消兜底**：匹配不到的文章不再被塞进「新闻」，而是在覆盖检查里报出来
- 归一化时**保留原始 WP 分类**（`wpCategories` 字段）——上次就是丢了它，导致事后无法核对

**第 1 步 · 全量重新抓取**
```
WP_BASE_URL="https://www.tuidang.org" npm run migrate:wp -- --per-page 20 > artifacts/phase5/normalized-full.json
```
不加 `--max-posts`，抓满 15,513 篇。走代理会慢，预计一两个小时。

**第 2 步 · 覆盖检查**
```
npx tsx scripts/check-wp-taxonomy.ts --rest https://www.tuidang.org
```
必须是「未覆盖 0」才继续。

**第 3 步 · 试验导入 ≤1,000 篇**
```
npm run migrate:import -- artifacts/phase5/normalized-full.json --dry-run
```
先 dry-run 看分类分布对不对，再小批量 `--apply` 一千篇，检查：
各分类篇数、`section=resources` 是否真的分出来了、301 跳转是否正确。

**第 4 步 · 备份 + 清空 + 全量导入**
先把现有 `cms_articles` 导出一份（正文是干净的，只有分类错）。
确认备份可用后清空 `cms_articles`、`cms_article_category_map`、`cms_redirects`，
再全量导入 15,513 篇。

**第 5 步 · 收尾**
核对各分类篇数与上表是否一致；确认「新闻」为 0 篇后删掉它；重建跳转表。

> 第 4 步不可逆。第 3 步确认无误、且备份存在之后再做。
